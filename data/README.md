# Example Data

`diamond.dag` has three node layers, six weighted edges, two sources, and two
outputs. `diamond.batch` contains two inputs with non-unit sources. The exact
results are `[29, -185]` and `[1, -19]` in output-list order.

`cos_su2_n2.dag` is generated by:

```bash
./build/bdg_make_cos_fixture --order 2 --output data/cos_su2_n2.dag
```

It has five node layers (including sources and sink), 56 edges, two sources,
and one sink output. It sums connected spin-up/spin-down permutation products
over both A/B site choices for each of two interactions. The generator retains
the same DAG structure for every input matrix.

For order `n`, weights represent a row-major `4n x 4n` matrix. A row or column
has index `2 * vertex + site`, with `site` in `{0,1}` and `vertex` in `[0,2n)`.
Vertices `[0,n)` and `[n,2n)` label the two spins. Only same-spin matrix entries
are used. Both endpoints of an interaction share its site choice. Diagonal
entries need not vanish; the two spin blocks need not agree. Source values of
one implement the site sum. Other source values are permitted by the generic
evaluator but alter that interpretation.

The independent CPU test enumerates both spin permutations, keeps pairs whose
union connects all interactions, and sums all `2^n` site assignments with the
product of permutation signs. This is checked against the generated graph at
orders 1--4. No shift factors or coupling/integration prefactors are included
in this small sample.

The CLI's default weights are reproducible synthetic numbers, not sampled
Green functions. Supply a `BDAG_BATCH` file for controlled application-specific
inputs. GPU benchmarks test evaluation of a fixed supplied graph; they do not
benchmark the CoS graph generator or establish a physical observable.
